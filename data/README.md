# 📦 Data Directory

This directory contains **source files** and **generated artifacts** for the CustoFlow project.

## 📋 Structure

### ✅ Source Files (Version Controlled)

- **`faq_knowledge_base.json`** - Source FAQ database
  - This is the **master source** for all FAQs
  - Used by `tools/faq_tool.py` to load FAQ data
  - **DO NOT DELETE** - This is the source of truth

### 🔄 Generated Artifacts (Not Version Controlled)

- **`faq_index/`** - FAISS index for semantic search
  - Contains `faq_index.faiss` and `faq_metadata.pkl`
  - Generated by `tools/init_semantic_search.py`
  - Can be regenerated if needed
  - Stored in Supabase Storage for production

- **`kb_versions/`** - Knowledge Base version history
  - Used for A/B testing different KB configurations
  - Managed by `tools/knowledge_base_manager.py`
  - Can be regenerated if needed

## 🗄️ Data Storage

**All runtime data is now stored in Supabase:**
- ✅ Orders → `orders` table
- ✅ Tickets → `tickets` table
- ✅ Sessions → `sessions` table
- ✅ Messages → `messages` table
- ✅ Feedback → `feedback` table
- ✅ Analytics → Calculated from database
- ✅ Agent Refinements → `agent_refinements` table
- ✅ KB Updates → `kb_updates_from_feedback` table
- ✅ Conversation Summaries → `conversation_summaries` table

## 🚫 Files NOT in this Directory

The following files are **NOT stored here** (they're in Supabase):
- ❌ `orders.json` - Use Supabase `orders` table
- ❌ `tickets.json` - Use Supabase `tickets` table
- ❌ `sessions.json` - Use Supabase `sessions` table
- ❌ `feedback.json` - Use Supabase `feedback` table
- ❌ `conversation_history.json` - Use Supabase `messages` table
- ❌ `analytics.json` - Calculated from database

## 🔧 Regenerating Artifacts

If you need to regenerate the FAISS index:

```bash
python -m tools.init_semantic_search
```

This will:
1. Load FAQs from `faq_knowledge_base.json`
2. Generate embeddings using Sentence Transformers
3. Create FAISS index in `data/faq_index/`
4. Upload to Supabase Storage (if configured)

## 📝 Notes

- The `data/` directory is primarily for **source files** and **cached artifacts**
- All **runtime data** is stored in **Supabase PostgreSQL**
- The FAISS index can be stored in **Supabase Storage** for production
- This keeps the repository clean and ensures data persistence
